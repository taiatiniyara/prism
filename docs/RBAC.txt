Role Based Access Control:

Roles:
    1. SA: Super Admin
    2. BMO: Benchmarking Officer
    3. BLO: Benchmarking Liason Officer
    4. DAO: Data Acquisition Officer
    5. CEO: Chief Executive Officer
    6. CON: Consultants
    7. AFF: Affiliates
    8. ALL: Allies
    9. MGR: Manager
    10: EXE: Executive

Organisations:
 - Every organisation can either be a utility or not.
 - Each organisation will have BLO's, a CEO, and DAO'SA

BMO:
    - The admin user of the whole system
    - Has access to all features

BLO:
    - Admin user for the utility
    - Has access to all utility related features
    - Manages utility users
    - Manage utility service-areas and generators
    - They will have full access to the who utility data entry workflow

DAO:
    - DAO groups will be divided according to dataLabelCategory e.g. DAOF: Data Acquisition Officer Finance
    - They will only access features limited to their data label category e.g. they will only enter data entries under their data label category

CON:
    - Once approved by the BMO, BLO's can assign consultants to their utility
    - We may want to have a JSON object inside the organisation table

AFF, ALL: 
    - These two roles will have access only to the Dashboard page. Nothing else.

EXE, MGR: 
    - The are utility managers and executives who will have a read-only access to utility related features.

CEO: 
    - CEO will approve data entry done by the BLO and DAOs
