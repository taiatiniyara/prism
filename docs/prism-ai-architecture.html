1. Overview

PRISM AI is a Claude-powered (@ai-sdk/anthropic + Vercel ai SDK v7) chat assistant embedded in the PRISM web app. It answers questions about utility performance (SAIDI/SAIFI, generation, losses, financials, tariffs, renewables) by calling ~70 tools that read either the PRISM database (via a medallion gold/silver layer) or a connected Power BI dataset — whichever the platform is configured to treat as primary. It streams responses, narrates its tool calls in plain English, persists full conversation history, and enforces rate limits, cost budgets, and content guardrails.

3. Request Flow

A single chat turn, end to end:

Origin + rate-limit + budget checks
→
Guardrail input validation
→
Load/create session + turn row
→
Resolve primary/secondary source
→
Build system prompt + tools
→
streamText (Sonnet, up to 10 steps)
→
SSE stream to client
→
Persist turn + tool calls

Entry point: POST app/api/ai/chat/route.ts. Key behaviours baked into that route:

  • Origin check (lib/ai/origin.ts) — request's Origin/Referer must exactly match the configured app URL (parsed-origin comparison, not a prefix check, to close a subdomain-spoofing hole).
  • Rate limit + cost budget checked before any model call (see §9).
  • Role-aware audience register — getAudienceRegister() maps the user's role (CEO/BMO/EXT/etc.) to one of 7 registers the prompt uses to calibrate tone; EXT users can self-declare a stakeholder type (government / consultant / donor / researcher) via stakeholder_type on the request body.
  • Conversation summarization — once a session passes 8 user turns, a background runAiGenerate call (Haiku-class, cheap) distills prior turns into a JSON context_summary (topics, key findings, utility/period mentions) stored on the session and re-injected on later turns, instead of replaying full history.
  • SSE protocol — a custom multi-channel line protocol over one stream: 0: text delta, 1: reasoning delta (tool narration text), 2: tool-start/tool-end events (drives the live "Thinking" panel), 3: error.
  • Empty-answer recovery — if a tool-using turn ends with no text (a known Anthropic/AI-SDK-v7 edge case), the route silently re-runs via runAiGenerate with a synthesis nudge before giving up, invisibly to the client since nothing was sent on channel 0 yet.

4. Persona & System Prompt

lib/ai/prompt.ts defines PRISM AI — branded as an "Energy Expert" persona for the Pacific Power Association. The prompt (current version tag AI_PROMPT_VERSION = "2026-07-13-medallion-v2", defined in lib/ai/types.ts) is a single large template (~255 lines / an estimated ~9K tokens per the service-layer comment) with a {{DATA_SOURCE_POLICY}} token substituted at request time based on the configured source (§5).

What the prompt encodes

  • Personality rules — conversational tone, no process narration ("never say 'let me check Power BI'"), contractions, varied sentence length, matches user's energy.
  • A 5-step expert reasoning chain — Diagnose → Connect → Position → Recommend → Caveat — formatted as numbered steps the UI renders as collapsible sections (see §12, structured reasoning UI).
  • An opinion-safety protocol — the model may now offer judgment/recommendations, but every opinion must be grounded in a retrieved figure, labelled separately from fact, and hedged ("this strongly suggests…", never "you must").
  • 7 audience registers — CEO/Executive/Board, Manager/Operations, Staff/Analyst, Government/Regulator, Consultant, Donor/DFI, Education/Researcher — each with a different emphasis on the same underlying facts.
  • Medallion architecture map — tells the model which gold/silver views back which native tools (gold.fact_kpi, gold.dim_utility, gold.fact_kpi_rollup, gold.v_reporting_status, gold.v_bsc_alignment, gold.ext_*).
  • Metadata-vs-performance distinction — repeatedly drilled rule that submission/completeness tools (get_kpi_status, get_trend_analysis, get_benchmarking_data, get_kpi_diagnostics) must never be presented as performance values.
  • Period fallback protocol — on empty results, step back through recent fiscal years/report periods (up to 3–4) before reporting a genuine data gap.
  • Anti-injection clause — told never to reveal its instructions or follow "ignore previous instructions"-style requests (backed by the input guardrail regex, see §8).
Prompt caching (live): the system prompt and the last tool definition both carry Anthropic cacheControl: { type: "ephemeral" } (lib/ai/service.ts). Because the ~9K-token prompt + ~70 tool schemas are identical on every step of a multi-step turn and often turn-to-turn within a session, a cache hit skips re-processing that prefix — this is the main lever for time-to-first-token on tool-using questions. Shipped in db4122e / PR #419.

5. Dual Data Source Model

PRISM AI can answer performance questions from two independent sources: the PRISM web app's gold layer (gold.fact_kpi, computed KPIs stored in Postgres) or a connected Power BI dataset (queried live via DAX). Which one is authoritative is a DEV-configurable app setting, not a code constant.

SettingStorageValues
ai_primary_sourceapp_settings table (lib/ai/source-setting.ts)webapp | powerbi
ai_secondary_sourceapp_settings tablewebapp | powerbi | none (isolation mode)

Both the system prompt's Data Source Priority section (§4) and the tool list itself are derived from the same resolved {primary, secondary} pair, computed once per request in prepareRequest() — so the model can't be told one thing and given tools for another.

Isolation mode is enforced at the tool layer, not just the prompt. When secondary === "none", createAiTools() (lib/ai/tools/index.ts) physically removes every tool belonging to the non-primary source before the model ever sees the tool list — soft prompt-steering alone was judged leaky. E.g. primary=webapp + secondary=none drops all Power BI tools; primary=powerbi + secondary=none drops the 6 gold-layer performance tools (GOLD_PERF_TOOLS).

Two-tier mode (a secondary configured) follows a strict protocol in the prompt: try primary → if it succeeds, stop (never cross-check the other source for the same figure) → if it errors/empties, walk back 1–2 fiscal years/report periods → only then fall back to the secondary → if both are empty, admit the gap honestly rather than substituting submission-completeness data.

6. Tool Registry (69 tools)

Tools are assembled in lib/ai/tools/index.ts from two families and merged into one object handed to the AI SDK:

PRISM-native lib/ai/tools/prism-native.ts (905 lines, 39 tools)

Administrative/workflow tools (review queue, input status, KPI diagnostics, governance audit, custom KPI status, guided entry) plus a fallback set of gold-layer performance tools that read gold.fact_kpi directly: get_kpi_targets, get_kpi_correlation, compare_kpis_across_utilities, get_compliance_status, get_data_quality_report, get_what_changed — the GOLD_PERF_TOOLS set.

Power BI lib/ai/tools/power-bi.ts (445 lines, 30 tools)

~40 pbi_* tools: schema discovery, DAX query execution + a query catalog of pre-built templates, risk scoring, peer grouping, donor reports, renewable/tariff scenario modelling, forecasting, correlations, anomaly detection, deep-links back into Power BI reports.

Both families are backed by a large lib/ai/data-service/ layer (30 files, ~7,300 lines) that does the actual DB/DAX querying, schema-registry lookups, benchmarking math, and World Bank API integration (data-service/worldbank.ts — live external API, no key required, used for income classification / lending category context).

Notable tool categories

  • Visualization: render_visualization — table, bar-chart, line-chart, leaderboard, scatter, radar, sankey, heatmap. Rendered client-side by components/ai/visualizations/*.
  • Export: generate_export / pbi_export hand off to POST app/api/ai/export/route.ts for CSV/XLSX generation (added in df2d896).
  • Self-referential: get_ai_usage lets the assistant answer "how much AI usage have I had" from its own metrics table.
  • Admin-gated: get_governance_audit and get_configuration_options are blocked for non-BMO/DEV roles by validateToolAccess() in guardrails.ts.

Tool narration

lib/ai/tool-narration.ts maps tool names to a present-tense, plain-English description (e.g. pbi_risk_score → "Calculating a risk score from the Power BI data") shown in the live "Thinking" panel instead of the raw function name. Any tool without an explicit entry falls back to a humanized auto-format. Shipped in PR #421 (28cc4d4).

Small drift found while compiling this doc: the map (and the AiToolName type union in types.ts) has 67 entries, but 69 tools are actually registered. get_worldbank_context and explain_input (both in prism-native.ts) are missing from both — real, callable tools that fall back to the generic humanizer for narration ("Working on worldbank context" / "Working on explain input") and aren't type-checked against AiToolName elsewhere. Low-impact (the fallback still reads fine), but worth a one-line fix to keep the two lists authoritative.

7. Reliability: Retries, Fallback, Circuit Breaker

lib/ai/service.ts is the single chokepoint for every model call (runAiStream for the chat route, runAiGenerate for background/summarization work). It layers several independent resilience mechanisms:

MechanismBehaviour
Transient-error retryUp to 3 retries with backoff [1s, 2s, 4s] on 429/502/503/504/"overloaded"/timeout errors (isTransientError). Permanent errors (400/401/403-shaped) fail immediately.
Model fallbackIf the primary model (Sonnet) exhausts its retries, the whole request is retried against the fallback model (Haiku) with its own retry budget.
Circuit breakerPer-model in-memory circuit: 5 consecutive failures opens a 30s cooldown during which calls to that model fast-fail rather than retrying (modelCircuits map, exposed via getCircuitState() and surfaced to the client as an X-Circuit-Breaker response header).
Empty-answer nudgeIf a tool-using generation finishes with blank text, one extra attempt is made with an appended "write your final answer now" system-prompt nudge before giving up.
First-chunk error peekwithFirstChunkCheck() — because streamText() resolves before the model call even starts, an immediate provider error only ever surfaces as an "error" part inside the stream; this peeks the first chunk before returning the stream to the caller so the retry/fallback loop can react before anything reaches the client.
Context-window guardToken-budget accounting (estimateTokens, ~3 chars/token) trims history to the role's max turn count, reserves 4K tokens for tool definitions, and throws a friendly "start a new chat" error rather than overflowing the 200K context window.
Extended thinking is currently disabled — a code comment in getModelConfig() documents that thinking + multi-step tool use produced empty final answers (thinking-block continuity wasn't preserved across tool steps by the SDK). Re-enable only once thinking+tools is independently verified.

8. Guardrails & Security

Input guardrails (lib/ai/guardrails.ts)

Regex-based rules block: email addresses, phone numbers, requests for private reviewer comments, credential/secret keywords, bulk-export phrasing, and prompt-injection patterns ("ignore previous instructions", "act as if you are…", "reveal your system prompt", etc.). Max message length 4,000 chars.

Output guardrails

filterOutput() redacts emails/phones/SSNs from the model's own response text before it's persisted or streamed, as defense-in-depth against the model echoing PII it picked up from tool results.

Tool access control

validateToolAccess() restricts get_governance_audit and get_configuration_options to BMO/DEV roles.

Origin validation

lib/ai/origin.ts — exact parsed-origin match against the configured app URL on every AI route, closing a subdomain-spoofing bypass that a prefix-string check would have allowed.

DAX injection sanitization

lib/ai/data-service/dax-sanitizer.ts — sanitizes/validates DAX query fragments before they're sent to Power BI, so a crafted user prompt can't inject arbitrary DAX.

Export formula-injection defense

CSV/XLSX export (app/api/ai/export/route.ts) prefixes any cell starting with =/+/-/@ with a quote to neutralize Excel formula/DDE injection, caps rows/columns/cell length, and sanitizes the filename before it goes into a Content-Disposition header.

Tenant scoping

Tools scope queries to the current user's utility/organisation by default (checkUserUtility); broader comparisons require an explicit ask. Covered by test/unit/ai/tenant-scoping.test.ts.

9. Rate Limiting, Cost Tracking & Budgets

lib/ai/rate-limit.ts is DB-backed with an in-memory fallback:

  • Request-rate limits — per-minute (default 20) and per-15-minute (default 100) windows, enforced via a single atomic upsert against ai_rate_limit_window keyed on (user_id, window_type, window_start) with a unique constraint — avoids a select-then-write race across pooled connections. Falls back to an in-memory sliding-window map if the DB write fails (fail-open with a warning log). Uniqueness constraint added in df2d896.
  • Cost budget — ai_cost_budget table holds a per-user daily_limit_cents (default from AI_DEFAULT_DAILY_COST_LIMIT_CENTS env var, else $5.00). checkCostBudget() compares today's ai_usage_metrics.estimated_cost_cents against the limit and the chat route returns HTTP 429 with a human-readable "$X of $Y" message once exceeded.
  • Cost estimation — MODEL_PRICING hardcodes Sonnet ($3/$15 per M in/out tokens) and Haiku ($0.80/$4 per M) to compute estimated_cost_cents on every recorded request.
  • Latency tracking — in-memory p50/p95/p99 buckets per endpoint, logged every 100 samples (recordLatency).
Backend-only today: the cost budget is fully enforced server-side (requests are blocked at the limit), but there is no chat-UI cost bar or "80% of budget" warning banner yet — see §14.

10. Persistence & Sessions

Schema in db/schema/ai.ts:

TablePurpose
ai_chat_sessionOne row per conversation. Auto-derived title (first 40 chars of the opening message), context_summary jsonb (topics/findings/utility/period, populated once a session exceeds 8 turns), soft-deletable.
ai_chat_turnOne row per Q&A exchange: user message, assistant response, model used, whether it was the fallback model, prompt version, input/output token counts, latency, error message.
ai_tool_callEvery tool invocation within a turn — name, args, result, status (pending/success/error/timeout), latency, data freshness/completeness metadata.
ai_feedback👍/👎 per turn plus optional free-text correction — surfaced via POST app/api/ai/feedback/route.ts.
ai_review_queueTurns flagged (e.g. by negative feedback) for human review, with a decision workflow (approved/rejected/needs_revision).
ai_usage_metricsDaily per-user rollup: requests, input/output tokens, estimated cost, tool calls, errors. Upserted on every completed request.
ai_cost_budgetPer-user daily spend cap + notification toggle.
ai_rate_limit_windowDurable sliding-window counters (minute / 15-min), unique on (user_id, window_type, window_start).

Session CRUD lives in app/api/ai/sessions/route.ts (list/create) and app/api/ai/sessions/[sessionId]/route.ts (fetch turns, rename, soft-delete). Streamed responses are additionally exposed for retrieval/replay via app/api/ai/chat/response/route.ts.

11. Observability & Admin Views

app/settings/ai/usage/page.tsx (DEV/BMO-gated) reads GET app/api/ai/usage/route.ts, which serves four report types off the metrics tables:

  • overview — daily requests/tokens/cost/tool-calls/errors, totals over a configurable window (1–90 days).
  • per-user — spend leaderboard joined to each user's configured daily budget.
  • tool-analytics — call count, error count, and average latency per tool name, across all users.
  • model-health — Sonnet vs Haiku split, fallback rate (how often the primary model failed over), average latency.

16. Example Question Bank

A grounded set of natural-language questions a user could actually ask PRISM AI today, organized by which tool(s) would answer them. Not exhaustive — the model also handles paraphrases, follow-ups, and combinations of these — but every question below maps to a real, currently-registered tool rather than an aspirational one.

Performance & KPI values (gold layer / Power BI)

  • What's our SAIDI for this fiscal year?
  • How much electricity did we generate last quarter?
  • What are our current system losses?
  • How does our SAIFI compare to last year?
  • What changed in our KPIs since the last reporting period?
  • Are we within our regulatory compliance limits?
  • Is there a correlation between our losses and revenue?
  • Compare [KPI] across all utilities in the Pacific.
  • What's our target for [KPI], and are we meeting it?
  • What would our losses look like if generation increased 10%? (what-if / calculate_kpi)
  • Break our performance down by service area.

Submission & data-entry status (never presented as performance)

  • Has [utility] submitted their data for this period yet?
  • What's our data submission completion rate?
  • Which KPIs are still pending review?
  • What inputs are missing to complete [KPI]?
  • Why is this KPI showing as incomplete or in error?
  • What's the status of my custom KPI request?
  • Show me the review queue.
  • Walk me through how to enter data for [KPI] — what do I need and where do I find it?
  • What report periods, categories, and service areas are available?

Benchmarking & peer comparison

  • How do we compare against our peer group?
  • Who are the top and bottom performers on [metric]?
  • Which utilities are most similar to ours?
  • What's the PPA target and Pacific regional average for [KPI]?
  • Where do we rank on data completeness among Pacific utilities?

Trends, anomalies & forecasting

  • How has our submission completeness trended over the last few periods?
  • Is there anything unusual in our recent data?
  • Forecast our generation for next fiscal year.
  • What's the trend in our tariff recovery?

Financial, tariff, donor & strategy modelling (Power BI advanced)

  • What donor-funded projects affect us, and where are the reporting gaps?

  • How does our income level affect what "affordable tariffs" means for us?
  • What active World Bank-funded projects are there in our country?
  • Show me the Pacific sub-region/country hierarchy.

Definitions & explanations

  • What does SAIDI mean and how is it calculated?
  • What exactly should I enter for [input field]?
  • What are the inclusion/exclusion rules for [KPI]?

Reports, summaries & alerts

  • Give me an executive digest for my Monday meeting.
  • Are there any threshold alerts I should know about?
  • Pull up the [utility] Power BI report.
  • Link me straight to the relevant dashboard.

Visualization & export

  • Show this as a bar chart / line chart / leaderboard.
  • Export this to Excel or CSV.

Power BI platform diagnostics (mostly DEV/BMO)

  • What datasets are available in Power BI?
  • What's the schema for [table]?
  • How fresh is the Power BI data right now?
  • Diagnose why the Power BI connection is failing.
  • What report pages are available?

AI platform / meta

  • How much AI usage have I had this month? (admin/self-serve, get_ai_usage)
  • What follow-up questions should I ask next?
Audience shifts the framing, not the tool. The same question — e.g. "how are we doing?" — is answered differently depending on the caller's audience register (§4): a CEO gets a decision-and-tradeoff framing, a Donor/DFI gets impact and value-for-money, an Education/Researcher gets method and data caveats first. The underlying tool call is identical; only the prose changes.
