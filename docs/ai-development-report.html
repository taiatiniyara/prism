validateToolAccess now gates get_governance_audit and get_configuration_options behind DEV/BMO roles. Previously the ADMIN_ONLY_TOOLS array was empty — the validator was a no-op.

Both system prompts now include explicit security sections instructing the LLM to refuse attempts to modify, override, or extract system instructions via indirect phrasing, translation, role-playing, or delimiter tricks.

2.6 Error Message Sanitization

AI chat route no longer leaks raw error messages to clients. Errors are logged server-side via console.error + recordError. Clients receive a generic "An unexpected error occurred." response.

3. Data Access & Organisation Scoping

3.1 CRITICAL — Cross-Utility Data Leakage Fixes

PRISM is a multi-tenant platform where competing electricity utilities share the same database. The following vulnerabilities were discovered and fixed:

#VulnerabilityFix
1all_utilities flag trusted the LLM with no server-side role check. Any user could see all utilities' data by prompting the LLM.All data services now enforce hasGlobalUtilityAccess(user) — non-global users are scoped to their org regardless of what the LLM requests.
2Benchmarking tool hardcoded forceAllUtilities: true — every user saw every utility's rankings.Benchmarking now respects org scope unless user has global access.
3Scorecard queries had no org filtering — a BLO from Utility A could see Utility B's scorecard.Added userOrgId filter to listScorecardInputRows. Non-global users are scoped via WHERE clause.
4Report period IDs not validated against user's org — any period ID could be queried.Diagnostics, performance, and scorecard data services now validate ownership of requested periods.

3.2 Scorecard Approval Bypass

The scorecard aggregator historically required KPIs to reach Approved status. AI tools now bypass this gate:

  • buildScorecardSnapshot accepts { includeUnapproved: true }
  • When set, all KPI rows are included regardless of approval state. Missing actuals/targets default to 0 with off_track status.
  • Regular web UI continues using the strict path.

3.3 Scorecard Data Availability

listScorecardInputRows previously used FROM kpi INNER JOIN, returning 0 rows when no KPI values existed. Added { includeAllDefinitions: true } option that uses FROM kpiDefinitions LEFT JOIN kpi — returning all KPI definitions for a period with NULL values where no KPI has been calculated.

3.4 Period Auto-Resolution

All AI data services now auto-resolve report periods when not explicitly provided. They accept an optional year parameter (e.g., 2023) and resolve it to the correct numeric period ID via EXTRACT(YEAR FROM report_date). This eliminates the LLM needing to know numeric period IDs.

5. KPI Calculation Engine

The AI can now compute KPI values on-the-fly using the existing formula engine from app/data-entry/kpi-worker/.

Pipeline

  1. User asks: "What's our SAIDI for 2023?"
  2. AI calls calculate_kpi({ kpi_names: ["SAIDI"], year: 2023 })
  3. System looks up KPI definition → resolves formula inputs from database → evaluates formula via new Function() → returns computed value
  4. Works even when KPIs haven't been pre-calculated by the background worker

Reused Functions

  • evaluateKpiFormula — Pure evaluator (no DB)
  • resolveFormulaInputValues — Reads actual data_entries for formula variables

8. Infrastructure & Performance

Tool Result Cache

lib/ai/cache.ts — Request-scoped in-memory cache with 30s TTL. GetReportPeriods results are cached and reused across tools within the same turn, eliminating duplicate database queries when multiple tools are called in sequence.

Tool Execution Timeouts

Every tool execute is wrapped in Promise.race with a 15-second timeout. A hung database query fails fast instead of waiting for the full 60s route timeout.

Input Token Budget

prepareMessages now approximate-counts input tokens (4 chars ≈ 1 token) and truncates at ~20K tokens, preventing context window exhaustion from long conversation histories.

Concurrency Limits

In-memory per-user concurrent request counter caps at 5 simultaneous requests. acquireConcurrencySlot/releaseConcurrencySlot tracked with cleanup in both streaming onFinish and error handlers.

Chatbot Telemetry Persistence

Capability resolution telemetry now persists to the error_logs database table alongside the existing console.log output. Includes matched capabilities, per-builder latency, fallback rates, and user ID.

Role-Based Page Access

/prism-ai page added to all 9 role prefix lists in lib/role-guard.ts — every role (BMO, BLO, CEO, DAOF, DAOH, DAOO, EXE, EXT, MGR, DEV) can now access the AI page.
