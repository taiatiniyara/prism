1. Architecture & System Consolidation

Two Systems → One

PRISM originally had two completely independent AI stacks — lib/ai/ (Vercel AI SDK tool-calling) and lib/chatbot/ (capability-based grounding). They shared zero code, used different DB schemas, and had redundant guardrails, rate limiters, and prompts.

Action: The entire lib/chatbot/ stack (30 files), app/api/chatbot/ routes, components/chatbot/ UI, db/schema/chat-history.ts, YAML question bank (1881 lines), and prompt generator script were deleted. All functionality consolidated into the single lib/ai/ system.

3. Security Hardening

Input Guardrails

RuleProtects AgainstStatus
PII-EMAILEmail addresses in user inputactive
PII-PHONEPhone numbers in user inputactive
PRIVATE-COMMENTSRequests for reviewer commentsactive
CREDENTIALSPassword/API key extraction attemptsactive
BULK-EXPORTBulk data export requestsactive
PROMPT-INJECTION"Ignore previous instructions" attacksactive

Multi-Turn Validation

All user messages in conversation history are now validated — not just the latest. Previously only the last message was checked, enabling multi-turn injection via earlier messages.

Output PII Filtering

LLM responses are filtered for emails, phone numbers, and SSNs before being persisted and streamed to the client. Applied in the onFinish callback of every stream.

Rate Limiting & Concurrency

Limit TypeValueImplementation
Requests per minute30In-memory sliding window
Tokens per day100,000DB-backed via ai_usage_metrics
Concurrent requests per user5In-memory atomic counter
Degraded modeAt 90% token usageFalls back to Haiku model

Prompt Injection Hardening

Both system prompts contain explicit security sections instructing the LLM to refuse any attempt to modify, override, extract, or bypass system instructions via indirect phrasing, translation, role-playing, delimiter tricks, or nested instructions.

Error Sanitization

Raw error messages, stack traces, and internal exceptions are never leaked to clients. All errors are logged server-side; clients receive a generic message.

Session Title Protection

Session titles derived from first messages are HTML-stripped and capped at 40 characters with ellipsis — preventing sensitive business content from being visibly exposed in the sidebar.

Export Route Security

Enforced max 50 columns, 1000 rows, 500 chars per cell. All cell values sanitized. Previously accepted arbitrary client data with no limits.

Empty Response Handling

If Claude returns empty text, users see a fallback message instead of a blank bubble.

6. KPI Calculation & Advanced Analytics

On-the-Fly KPI Calculation

calculate_kpi uses the existing formula engine from app/data-entry/kpi-worker/: looks up KPI definitions, resolves formula inputs from data_entries, evaluates via new Function(). Works even when KPIs haven't been pre-calculated by the background worker.

What-If & Sensitivity Analysis

calculate_kpi accepts hypothetical_values (scenario overrides) and sensitivity_variable (varies one input ±10%, ±25%, ±50% and returns how the KPI changes).

Cross-KPI Correlation

get_kpi_correlation computes Pearson correlation coefficients between all KPI pairs across utilities. Answers "do utilities with high system losses also have high SAIDI?" with strong_positive / moderate_positive / weak / moderate_negative / strong_negative labels.

Peer-Benchmark Target Setting

get_kpi_targets computes median, top quartile, and bottom quartile for each KPI across utilities. Returns suggested_target, gap_to_median, gap_to_top_quartile, and difficulty rating (easy / moderate / stretch / extreme).

Regulatory Compliance

get_compliance_status reads KPI limits from definitions and flags values below minimum, above maximum, or negative — with severity and descriptions.

Risk Assessment

get_risk_assessment computes a 0-100 risk score per utility with severity classification and flags (low completion, high pending, approval gaps, zero endorsements).

7. System Prompt Engineering

"What Performance Means"

Defines performance as operational, financial, customer, and development outcomes — not data submission progress. Priority order: scorecard → diagnostics → benchmarking → trends. Explicit rule: performance questions must hit scorecard tools first, not status tools.

Role-Specific Tuning

Route-level injection of role context into the system prompt: BMO/DEV → thorough, technical, all-utility access; BLO → actionable with educational context; CEO → strategic trends, avoid minutiae; EXT → limited access focus, platform context; Default → actionable tasks, data quality, next steps.

Citation & Benchmark Context

Core Rule 2 mandates citations: "(Source: [utility], [period], [tool_used])". Core Rule 7 requires benchmark context via get_industry_benchmarks on every KPI value.

User Context Awareness

LLM instructed that tools auto-scope to the user's organisation — no need to ask "which utility?"

Prompt Version Tracking

AI_PROMPT_VERSION = "2026-06-10" stored on every ai_chat_turn. CHATBOT_PROMPT_VERSION column added to schema.

9. Infrastructure & Performance

Tool Result Cache

lib/ai/cache.ts — Request-scoped in-memory cache (30s TTL). GetReportPeriods results reused across tools within the same turn.

Tool Execution Timeouts

Every tool wrapped in Promise.race with 15-second timeout. Hung DB queries fail fast.

Input Token Budget

prepareMessages approximate-counts input tokens (4 chars ≈ 1 token) and truncates at ~20K tokens.

Circuit Breaker

After 5 failures within 60 seconds, tool enters cooldown. recordToolFailure / resetToolCircuit integrated into withTimeout wrapper.

Conversation Summarization

Auto-detects conversations exceeding 8 turns. Injects system message instructing the LLM to summarise context before answering.

Concurrency Limits

Max 5 concurrent AI requests per user. acquireConcurrencySlot / releaseConcurrencySlot tracked with cleanup in streaming onFinish and error handlers.

Tool Latency Tracking

latency_ms computed as Date.now() - startedAt. Previously hardcoded to 0. Populated on both success and failure.

Admin Session Visibility

GET /api/ai/sessions?admin_all=true allows DEV/BMO to view all users' sessions.

Error Message Persistence

aiChatTurn.error_message populated with error text (truncated to 500 chars) on failed turns.
