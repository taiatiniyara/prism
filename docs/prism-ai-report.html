3. System Prompt & Persona

lib/ai/prompt.ts (151 lines)  |  Version: 2026-06-19-v3

Personality

Warm, collegial, knowledgeable colleague. Uses "you"/"your utility". Contractions, varied sentence length, natural openers. Never narrates process — tool calls happen silently. No "Let me check Power BI" or "I'll pull that up."

Data Source Priority

1. Power BI (pbi_match → pbi_query) 2. Previous FY fallback once 3. PRISM-native tools 4. Honest gap report. One-failure rule modified: try previous FY before switching source.

8 Core Rules

Never fabricate. Empty = try previous period first (up to 3-4). Just query — don't pre-check. Give data context. Respect scope. Protect sensitive data. Be upfront about gaps. Benchmark when helpful.

4. Expert Reasoning Chain

lib/ai/prompt.ts:46-54

  1. Diagnose — What does this number mean for THIS utility, at THIS scale, in THIS context? A 12% loss rate means something different for a 5,000-customer atoll utility vs. a 200,000-customer national grid.
  2. Connect — Relate to other metrics. Energy systems are causal chains: high losses → revenue gap → deferred maintenance → reliability decline.
  3. Position — Benchmark against PPA target, Pacific regional average, and peer group. Is this good, concerning, or critical?
  4. Recommend — Single highest-leverage next step with reasoning. Lead with it.
  5. Caveat — Name assumptions and what would change the read (data gaps, one-off events, missing context).

The reasoning chain appears as collapsible, numbered sections in the chat UI. Each step is marked with its label and rendered as an expandable <details> element. The frontend parses reasoning outputs matching the pattern "1. Diagnose ..." through "5. Caveat ...".

Opinion-Safety Protocol

  • Ground every opinion in numbers actually retrieved — no retrieved figure → no quantitative claim
  • Label the layer — state the fact, then the read: "Your SAIDI is 320 min (PPA target 360) — solid. But it's risen 40%..."
  • Calibrate confidence — "this strongly suggests...", "one likely driver...", "I can't tell from this data alone..."
  • Stay in lane — energy/utility performance, economics, strategy only. Flag legal/procurement/safety-critical for qualified professionals
  • Recommendations are starting points — "Worth investigating", "I'd prioritise" — never "you must"

7. Streaming Protocol

app/api/ai/chat/route.ts:396-505  |  components/ai/chat-panel.tsx

Wire Format (SSE via ReadableStream)

0:{"delta":"text fragment..."}        ← text delta (character-by-character)
1:{"type":"reasoning-delta",...}     ← reasoning/thinking content
2:{"type":"tool-start","toolName":...} ← tool call started
2:{"type":"tool-end","toolName":...,"resultSummary":...} ← tool call completed
3:{"error":"message"}                 ← stream error

Response Headers

HeaderValue
Content-Typetext/event-stream
X-Session-IdSession ID for this conversation
X-Turn-IdTurn ID within the session
X-ModelModel actually used (primary or fallback)
X-Was-Fallback"true" or "false"
X-Prompt-VersionCurrent prompt version (e.g. 2026-06-19-v3)
X-Circuit-Breaker"open:Nseconds" if circuit breaker is active

Client-Side Character Reveal

  • Text deltas accumulated in pendingContentRef
  • Revealed character-by-character via requestAnimationFrame (3 chars per frame)
  • Buffer cap: 12,000 chars — beyond that, instant display
  • Message input capped at 4,000 chars (MAX_CHARS)
  • Streaming cursor CSS class (streaming-cursor) for blinking caret effect
  • Abort via AbortController — stop button in chat input

Post-Stream Sync

On stream completion, the client calls POST /api/ai/chat/response to sync the final content to the server. Tool calls, token counts, and model info are persisted to aiChatTurn and aiToolCall tables during onFinish.

DAX Sanitization (sanitizeDax)

lib/ai/data-service/dax-sanitizer.ts:52

  • Blocks DDL/DML: REFRESH, ALTER, CREATE, DROP, DELETE, INSERT, UPDATE, TRUNCATE, GRANT, REVOKE
  • Blocks dangerous patterns: INFO., DMV, SESSION, DISCOVER_*
  • Requires top-level EVALUATE / SUMMARIZECOLUMNS / DEFINE / ORDER
  • Max 8,000 characters

Origin Validation

All AI endpoints validate origin and referer headers against NEXT_PUBLIC_APP_URL or BETTER_AUTH_URL. Returns 403 on mismatch.

Route Protection

The /prism-ai route is protected by proxy.ts middleware which enforces Better Auth session + role-based route gating.

14. Period Fallback (June 2026)

lib/ai/prompt.ts:85-92  |  lib/ai/data-service/common.ts:98-115

New Feature — Implemented 2026-06-24

The AI now automatically tries progressively older reporting periods when the latest one returns no data. Previously it would report "no data" immediately.

How It Works

Power BI

Strategy: Try FY2026 → FY2025 → FY2024. If pbi_query returns empty rows or DAX error, step back one FY and retry before switching to PRISM-native.

Transparency: "FY2026 doesn't have data yet — here's what FY2025 shows."

PRISM Native

Strategy: Call get_configuration_options to see available periods (newest-first). Query period[0], then period[1], then period[2].

Rationale: Many Pacific utilities are 1-2 periods behind. The latest period may have no submitted data while the previous period is complete.

New Utility Function

resolveRecentPeriodIds(user, limit = 5): Promise<number[]> in lib/ai/data-service/common.ts:98. Returns the N most recent period IDs for the user's utility, ordered newest-first. Available for tools to use internally for auto-fallback.

Prompt Changes

  • Core Rule #2 updated: "Empty means empty — but try the previous period first" (up to 3-4 periods)
  • New "Period Fallback" section: Concrete instructions for both Power BI and PRISM native
  • Data Source Priority updated: Allows one FY fallback on Power BI before switching source
  • Transparency rule: "Don't silently skip periods" — always tell the user which period delivered the data
