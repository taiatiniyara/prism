1. Design Principles

1. A definition is a pure measure

Dimension words (Solar, Prepaid, Residential, Female…) never appear in a measure's name. Every "which one" is a dimension column on the entry row. 515 legacy definitions collapse to ~55–65 measures.

2. IDs in tables, names in views

Storage rows carry foreign keys only. The Silver view resolves every ID to its label. Renames are one-row updates, never data migrations.

3. Typed at the source

The single varchar(255) value is replaced by typed value columns. The database itself rejects a non-number in a numeric field, on every write path.

4. No NULL-as-"All"

Every dimension has an explicit All member and the column is NOT NULL. Eliminates the NULL ambiguity that silently broke formula bindings.

5. Read down, never write up

Bronze is written by data entry. Silver and Gold are derived, refreshed automatically, and read by the AI, dashboards, reports, and external tiers.

5. Gold Layer — Business Views

VIEW dim_utility

Flattened utility profiles: name, acronym, country, sub_region, utility_size, utility_type, ownership_type, entity_type, PPA membership, monthly reporting flag.

VIEW fact_kpi

Computed KPI results with: actual_value, target_value, meets_target flag, category, subcategory, unit, calculation_formula_version.

VIEW fact_kpi_rollup

Hierarchical rollups via GROUPING SETS: global × period, sub-region × period, sub-region × size × period, utility × period. Aggregates: avg, min, max, count, entries_meeting_target.

VIEW v_reporting_status

Workflow progress per utility × period: total_entries, approved_count, not_available_count, pct_complete, pending_with_role.

VIEW v_bsc_alignment

Strategy map joined to actual KPI values. Unwraps the BSC JSON hierarchy into relational rows with kpi_name, actual_value, target_value.

VIEW ext_data_entries / ext_kpi

External-tier slices: Approved-only, summary-level, per-utility visibility. No raw values exposed to paid tiers.

7. Typed Value Routing

One shared function — lib/data-entry/value-router.ts — used by every write path (UI, Excel import, API, future document extraction). Routes based on measure's data_type_id.

Data TypeValue ColumnInput Control
number / numeric / integer / decimalvalue_numeric<input type="number">
boolean / boolvalue_booleanYes/No select
option / selectvalue_option_idManaged list item select
text / stringvalue_string<input type="text">
// lib/data-entry/value-router.ts export type ValueColumn = "value_numeric" | "value_boolean" | "value_option_id" | "value_string"; const DATA_TYPE_TO_COLUMN: Record<string, ValueColumn> = { number: "value_numeric", boolean: "value_boolean", option: "value_option_id", text: "value_string", // ... aliases for numeric, integer, decimal, bool, select, string }; export function resolveValueColumn(dataTypeName: string | null | undefined): ValueColumn | null;
What this buys: The database rejects wrong-typed values on every write path. The "Infinity" class of defect becomes impossible. No more string parsing in the KPI worker — it reads value_numeric directly.

9. Migration Scripts

1. medallion-backfill-nulls.sql

Backfills NULL → explicit All member IDs on all dimension columns.
• customer_type_id NULL → 690
• payment_mode_id NULL → 720
• energy_provider_id NULL → 20
• energy_source_id NULL → 40
• energy_type_id NULL → 30
Includes verification SELECT at end.

2. medallion-migrate-values.sql

Routes varchar / boolean / text / numeric values into the 4 typed columns based on measure data_type.
• number-typed → value_numeric (from numberic_value or parsed varchar)
• boolean-typed → value_boolean (parsed Yes/No/true/false)
• text-typed → value_string (from text_value or varchar)
Parse failures (~90 rows: "Infinity" + placeholders) logged to data_entry_logs, not dropped.

3. medallion-collapse-measures.sql

Infrastructure for the 515→~55 measure collapse:
• measure_def_migration_map table
• create_measure_from_template() function
• map_legacy_to_measure() function
• v_measure_migration_summary view
Actual mapping data requires the classifier workbook (p1_dl_def_ids_raw.xlsx).

4. medallion-retire-endorsed.sql

Migrates all Endorsed (status_id=6) rows → Approved (status_id=5).
Reports count of affected rows via RAISE NOTICE.

5. medallion-silver-gold-views.sql

Creates schemas silver + gold, the materialized view, 7 gold views, refresh function, and all indexes. ~350 lines of SQL.
